APPENDIX A — COMPLETE SOURCE CHECKLIST (REPRODUCED VERBATIM)

COMPLETE WEBSITE SECURITY, RELIABILITY, SEO & PERFORMANCE CHECKLIST
Production Engineering Standard for AI-Assisted Website and App
Development

PURPOSE Use this checklist when building websites or applications with
AI-assisted coding tools such as Claude Code, Cursor, Lovable, Bolt,
Replit, or similar tools.

A production website should be: - Secure against hacking and
unauthorized access. - Protected against SQL injection, XSS, CSRF, and
other attacks. - Reliable, stable, and recoverable. - Optimized for
Google Search and indexing. - Integrated with Google Analytics and
Search Console where appropriate. - Optimized for mobile devices, speed,
and Core Web Vitals. - Compliant with applicable privacy and data
protection requirements. - Tested before deployment and monitored after
launch.

IMPORTANT SECURITY PRINCIPLE No website can be guaranteed 100%
hack-free. The objective is to minimize vulnerabilities, restrict the
impact of attacks, detect suspicious activity, and recover quickly.

1.  WEBSITE SECURITY AND PROTECTION

Implement: - SQL injection prevention using parameterized queries and
prepared statements. - XSS prevention through input/output handling,
context-aware escaping, and safe rendering. - CSRF protection using CSRF
tokens and Origin validation where applicable. - Secure authentication,
password storage, and session management. - Server-side authorization
and resource-level access control. - Login rate limits and temporary
throttling to reduce brute-force attacks. - API authentication,
authorization, and request validation. - HTTPS/TLS across the entire
website. - Security headers, including Content-Security-Policy (CSP),
HTTP Strict Transport Security (HSTS), X-Content-Type-Options, and
Referrer-Policy. - File-upload validation, size limits, safe storage,
and malware scanning where appropriate. - Clickjacking protection using
CSP frame-ancestors or X-Frame-Options. - Secret management. Never
expose API keys, database passwords, service-role keys, or private
tokens in frontend code. - Dependency vulnerability scanning and timely
updates. - Restricted administrative access and multi-factor
authentication (MFA). - Safe error handling. Never expose stack traces,
SQL errors, filesystem paths, or internal infrastructure details to
visitors.

Threats to address: 1. SQL Injection 2. Cross-Site Scripting (XSS) 3.
Cross-Site Request Forgery (CSRF) 4. Remote Code Execution (RCE) 5.
Broken Access Control 6. Insecure Direct Object Reference (IDOR) 7.
Server-Side Request Forgery (SSRF) 8. Directory Traversal 9. Session
Hijacking 10. Credential Stuffing 11. Brute-Force Attacks 12.
Clickjacking 13. File Upload Attacks 14. Open Redirects 15. API Abuse
16. Business Logic Vulnerabilities

2.  DATABASE AND SQL SECURITY

For Supabase, PostgreSQL, MySQL, MongoDB, or another database: - Use
parameterized queries and prepared statements. - Never build SQL by
concatenating untrusted user input. - Validate all incoming data on the
server. - Use database constraints such as NOT NULL, UNIQUE, CHECK, and
FOREIGN KEY where appropriate. - Implement Row Level Security (RLS)
where supported. - Apply least-privilege database permissions. - Never
expose database credentials in frontend code. - Never expose Supabase
service-role keys to browsers. - Enable RLS on every table containing
protected user data. - Write and test SELECT, INSERT, UPDATE, and DELETE
policies separately. - Prevent users from accessing another user’s
records. - Use database transactions for related operations. - Add
indexes for frequently queried columns. - Configure connection pooling
and query timeouts. - Maintain automated database backups. - Test
database restoration periodically. - Log sensitive administrative
operations without logging passwords, tokens, or other secrets.

SUPABASE-SPECIFIC RULE Do not assume that hiding a button or protecting
a frontend route secures the database. Enforce permissions through RLS
and server-side authorization.

3.  AUTHENTICATION AND USER ACCOUNT SECURITY

For login systems, registration, student portals, dashboards, and admin
panels: - Store passwords using Argon2id or properly configured
bcrypt. - Use single-use, expiring password-reset tokens. - Verify email
ownership where appropriate. - Set OTP expiry and attempt limits; apply
rate limiting. - Offer or require TOTP or another secure MFA method for
sensitive accounts. - Use secure session cookies with HttpOnly, Secure,
and appropriate SameSite settings. - Invalidate sessions server-side on
logout. - Rate-limit login attempts and detect abuse. - Require MFA for
administrators. - Implement role-based access control (RBAC) and
resource-level authorization. - Use secure account-recovery identity
verification. - Allow users to view and revoke active sessions where
appropriate.

Possible roles: - Super Admin - Admin - Manager - Staff - Customer -
Registered User - Guest

Define explicit permissions for every role. Never authorize an action
based only on a role name supplied by the client.

4.  API AND BACKEND SECURITY

-   Validate every API request.
-   Authenticate protected endpoints.
-   Verify resource ownership and authorization.
-   Implement API rate limiting.
-   Apply request-size limits.
-   Validate HTTP methods.
-   Restrict CORS to trusted origins.
-   Avoid exposing internal server information.
-   Verify webhook signatures securely.
-   Prevent replay attacks for sensitive webhook operations where
    applicable.
-   Set request and database timeouts.
-   Validate third-party API responses.
-   Implement pagination limits.
-   Protect against SSRF.
-   Never trust client-submitted prices, roles, permissions, or payment
    status.
-   Enforce sensitive business rules on the server.

Hiding an API endpoint from the browser does not make it secure.

5.  GOOGLE SEO OPTIMIZATION

ON-PAGE SEO - Use a unique SEO title for every public page. - Use a
unique meta description for every public page. - Use one clear H1
heading per page, with a logical H1/H2/H3 hierarchy. - Use readable,
SEO-friendly URLs. - Configure canonical URLs. - Add descriptive ALT
text to meaningful images. - Use descriptive internal links. - Use
relevant keywords naturally. - Publish unique, useful content. - Add
Open Graph metadata. - Add Twitter/X Card metadata where appropriate. -
Add breadcrumb navigation where relevant. - Ensure social sharing
previews work.

TECHNICAL SEO - Create and verify robots.txt. - Create and submit
sitemap.xml. - Configure a web manifest where appropriate. - Build a
custom 404 page. - Configure appropriate 301 redirects. - Enforce HTTPS
and a consistent canonical domain. - Use correct index/noindex
directives. - Add relevant structured data using JSON-LD. - Ensure

GOOGLE SEARCH CONSOLE - Verify domain ownership. - Submit the XML
